# Модель угроз

Активы — имя и телефон клиента, учётные записи, цены и публикация, токен Telegram, хранилище фотографий и резервные копии. Границы — браузер/HTTP, приложение/PostgreSQL, приложение/файлы, приложение/Telegram, внешний вход/origin.

| Угроза | Реализация | Проверка / зависимость |
| --- | --- | --- |
| IDOR, повышение роли и захват сессии | Роли Spring Security, отдельные DTO, отказ старой версии сессии, защита OWNER, обязательная смена временного пароля | HTTP-проверки |
| CSRF, XSS, clickjacking и SQL injection | CSRF Spring Security, вывод React plain text, CSP, DENY, параметры SQL и allowlist сортировки | Негативные HTTP и браузерные проверки |
| Подмена товара, цены и повтор POST | Транзакционная проверка публикации, категории, наличия и цены. Уникальный ключ и блокировка повторов | Конкурентный HTTP POST и stale price |
| Дорогие запросы и загрузки | Лимиты длины, страницы и времени запроса, ограничение HTTP-потоков и пула, формат/пиксели/размер фото, ограничение конвертаций | Нагрузочная и NAT-приёмка на стенде |
| Несанкционированный просмотр контактных данных | Доступ через защищённые API, cache-control no-store, PII исключается из аудита, обезличивание | Негативный доступ и API обезличивания |
| Обход edge, объёмные атаки и медленные соединения | Закрытие origin и лимиты proxy на этапе выпуска, forwarded headers отключены в приложении | Отдельный стенд и проверка IPv4/IPv6 |
| Ошибка Telegram и повтор внешнего уведомления | Снимок, durable outbox, таймауты, аренда и повтор. Внешняя доставка может дублироваться | Проверка с тестовым провайдером и контролируемым получателем |
| Утечка конфигурации и копий | Секреты в окружении, раздельные роли и окружения, шифрование и контроль доступа при выпуске | Инвентаризация стенда и восстановление |

Текст обработки и допустимость передачи контактов в Telegram подтверждает владелец перед выпуском. При удалении данных из Telegram и резервных копий действует отдельный процесс, учитывающий политику провайдера и сроки ротации копий.
