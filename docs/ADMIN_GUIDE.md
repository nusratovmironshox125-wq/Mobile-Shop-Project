# Управление магазином

1. Создайте первого OWNER по README, откройте /admin/login и войдите.
2. В настройках задайте публичное название, телефон, Telegram, адрес, ссылку на карту и ориентир. Это публичные контакты. Канал Telegram для заявок задаётся отдельно через окружение сервера.
3. Создайте товар как черновик. Задайте категорию, бренд и модель. Ссылка создаётся автоматически и не меняется при переименовании. Добавьте комплектацию с уникальным артикулом, ценой, наличием и нужными характеристиками. При скидке задайте меньшую цену и при необходимости интервал по Ташкенту.
4. Загрузите фото JPEG, PNG или WebP до 5 МБ, при необходимости привяжите его к комплектации. Затем поменяйте публикацию на «Опубликован». Архив скрывает товар, сохраняя историю. Категорию ноутбуков можно отключить в разделе категорий.
5. Откройте заявки, выберите запись, свяжитесь с клиентом и поменяйте статус. Обычный путь «Новая → Связались → Завершена». Для повторного открытия завершённой или отменённой заявки OWNER указывает причину.
6. OWNER добавляет администратора и передаёт показанный временный пароль отдельным защищённым каналом. Сотрудник меняет пароль при первом входе. Отключение и сброс пароля аннулируют доступ старой сессии.
7. OWNER просматривает аудит и состояние уведомлений. Для обезличивания заявки требуется подтверждение в её карточке.

## Исправления 11 ноября

- Возле «Заявки» на всех страницах панели виден общий счётчик непрочитанных. Он обновляется каждые 10 секунд в активной вкладке. Первый вход показывает накопленный счётчик; toast появляются для новых поступлений. При обрыве связи отображается предупреждение, после возврата данные берутся с сервера.
- «Новая» и выделение строки означают отсутствие просмотра этим сотрудником. Открытие успешно загруженной карточки отмечает её прочитанной только для вас. Бизнес-статус NEW остаётся до явного изменения. Счётчик другого администратора не уменьшается.
- На третьей и последующих страницах поступление не переключает страницу: появляется кнопка перехода к новым заявкам. Список/фильтры и страницы сохраняются в URL.
- Категория задаёт технический тип. Телефон — RAM, встроенная память, экран, процессор, камеры, аккумулятор, SIM/eSIM, ОС. Ноутбук — CPU/GPU, RAM, накопитель и его тип, экран, ОС, вес. Общие цена/цвет/наличие/скидка/рассрочка доступны обоим. У товара с вариантами прямая смена технического типа запрещена.
- Варианты старого смешанного товара показывают предупреждение и сохранённые чужие значения. Для исправления проверьте их, сохраните нужные данные в подходящих полях и явно подтвердите очистку. До подтверждения сервер не удаляет эти поля. Публичный API и страница их не показывают.
- «Артикул товара (SKU)» — уникальный код одной комплектации. Новые коды сохраняются в верхнем регистре без крайних пробелов; поиск не зависит от регистра. После сохранения код не меняется. Старые артикулы и снимки заявок сохраняются.
- «Ссылка на товар» доступна после сохранения, её можно открыть/скопировать. Черновик и архив по публичной ссылке недоступны.
- OWNER → Журнал показывает username на момент действия, роль, объект, время и раскрываемые изменения. Фильтры по логину, действию, объекту/артикулу и датам. Старые события без снимка отображают «Автор не сохранён». Пароли и клиентские контакты в diff не включаются.
- Каталог, категории/скидки, административные товары/заявки/журнал/администраторы/категории/очередь имеют страницы по 10. Избранное тоже показывает 10, используя ограниченный локальный список ID и актуальные серверные цены/видимость.
